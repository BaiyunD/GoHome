# 面板管理与分层策略（UIManager）

本页说明 `UIManager` 当前的 UI 路由与分层规则，重点覆盖 `PanelType` Page 命名升级与 Modal 归类约束。

## 当前分层

- `PanelType` 仅承载常驻/流程面板：
  - 常驻：`PanelType.HudStatus`、`PanelType.ActionBar`
  - Page：`PanelType.InventoryPage`、`PanelType.CraftPage`、`PanelType.TraitsPage`、`PanelType.RestPage`、`PanelType.EndPage`
  - 其他保持不变：`RandomEvent`、`Battle`、`CombatStats`
- Modal 轻覆盖层（**非 PanelType**）：
  - `EventNarrationModal`
  - `ResultToastModal`

## 路由约束（本轮保持不变）

- 打开 Page 时，`UIRouter` 仍会调用 `HideEventNarrationText()` 主动隐藏 narration。
- 本轮仅做语义化命名调整，不改 Page/Panel 路由行为。
- 不将 `EventNarrationModal`/`ResultToastModal` 塞入 `PanelType` 或 `UIStateMachine` 的 modal 栈。

## 入口与修改点

- 统一入口：`Assets/Scripts/Manager/UIManager.cs`
  - `OpenUIEntry(PanelType type)`
  - `CloseUIEntry(PanelType type)`
- Page 映射：`Assets/Scripts/Manager/UIStateModel.cs`（`UIPageMapping`）
- 典型常驻与页面组件：
  - `HudStatusPanel`
  - `ActionBarPanel`
  - `InventoryPage` / `CraftPage` / `TraitsPage` / `RestPage` / `EndPage`

## 验证要点

- 流程面板打开时仅关闭 `ActionBar`，不误伤 `HudStatus`。
- 打开任一 Page 后 narration 文本会被路由主动隐藏。
- Modal 组件不参与 `PanelType` 切换，不进入页面栈。
