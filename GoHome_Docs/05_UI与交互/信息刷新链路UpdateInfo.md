# 信息刷新链路 UpdateInfo（谁来刷、何时刷）

本页说明 `UIManager.UpdateInfo()` 的职责边界，以及常见“漏刷/重复刷”的问题应该从哪里改。

> 架构背景：[`../02_核心架构/整体设计.md`](../02_核心架构/整体设计.md)

## UpdateInfo 负责什么

- 统一执行有限刷新：`HudStatusPanel.RefreshStatus()`、`TraitsPage.Refresh()`
- 在刷新后收起事件叙述：`eventNarrationModal.Hide()`
- 降低各业务模块直接操作 UI 的需求（业务侧只负责改权威数据源）

> 说明：`UpdateInfo()` 不是“刷新所有可见面板”的总入口。战斗、事件等面板有各自刷新链路。

## 谁应该调用 UpdateInfo（推荐规则）

优先由两类时机触发：

1. **面板开关后**
   - 推荐入口 `OpenUIEntry/CloseUIEntry` 后立即调用一次
2. **关键权威数据变化后**
   - 例如 day/distance/玩家属性等变化事件回调中，集中触发一次

避免：
- 每帧刷新（性能与闪烁风险）
- 业务逻辑内部多层嵌套反复刷新（会放大“重复刷 UI”）

## 常见问题与定位

### 1) 漏刷：数据变了 UI 没变

优先检查：
- 触发点是否缺少 `UIManager.UpdateInfo()`（开关面板/流程结束/回合结算）
- 面板 `RefreshView()` 是否依赖了未设置的引用（例如 Manager 单例未注入）

### 2) 重复刷：同一次操作刷了多次，或出现闪烁

优先检查：
- 同一事件是否被重复订阅（典型：`OnEnable` 订阅但没在 `OnDisable` 解绑）
- 流程控制器是否在协程里多次调用 `UpdateInfo()`（可以合并到关键节点）

### 3) 刷新顺序错：面板刚打开就刷新但字段还没准备好

优先检查：
- `OpenUIEntry` 的顺序（先准备数据快照，再开 UI，再刷新）
- 战斗/事件等流程是否在 `Transit` 状态下立即刷新导致取到 0 值

## 怎么验（必须验证项）

- 前进/探索后：资源/进度变化能刷新到 UI
- 事件选择后：属性变化/物品变化能刷新到 UI
- 开始战斗后：敌人信息（例如 HP）首次显示不是 0/空
