# 整体设计

## 设计概览（基于当前代码）

GoHome 采用“Manager 单例 + 事件驱动进度 + UIManager 集中路由”的结构。

- **按生命周期分层（现状已迁移落位）**
  - **App 层**（`Assets/Scripts/App`）：启动与跨局基础设施（存档、场景切换、配置注册）。
  - **Session 层**（`Assets/Scripts/Session`）：一局会话的运行时状态（玩家/路线/背包/特性等）。
  - **Level 层**（`Assets/Scripts/Level`）：关卡流程调度（行动/前进/事件/战斗/结局）。
  - **UI 层**（`Assets/Scripts/UI`）：展示与交互；显隐与路由由 `UIManager + UIRouter + UIStateMachine` 控制。
- **进度与事件驱动**
  - `RouteProgressManager` 广播 day/distance/region 变化。
  - `GameManager` 订阅关键进度变化，触发结束判定。

## 关键入口

- 新游戏初始化：`GameManager.NewGame()`
- 行动入口：`ActionBarPanel` -> `ActionManager`
- 前进/探索流程：`AdvanceFlowController`
- 事件与战斗：`EventManager`、`BattleManager`
- UI 路由：`UIManager.OpenUIEntry/CloseUIEntry`

## UI 分层现状

- `PanelType` 维持 Page/Panel 路由：
  - 常驻：`HudStatus`、`ActionBar`
  - Page：`InventoryPage`、`CraftPage`、`TraitsPage`、`RestPage`、`EndPage`
  - 其他：`RandomEvent`、`Battle`、`CombatStats`
- Modal 轻覆盖层（非 `PanelType`）：
  - `EventNarrationModal`
  - `ResultToastModal`
- 行为约束保持不变：
  - 打开 Page 时，路由仍会主动隐藏 narration。

## 修改建议

- 改流程逻辑：先查 `AdvanceFlowController` 与相关 Manager。
- 改 UI 策略：优先改 `UIManager` 与 `UIStateModel`，避免在业务处散落 `SetActive`。
- 改 Inspector 绑定字段：同步加 `FormerlySerializedAs` 保障序列化兼容。
