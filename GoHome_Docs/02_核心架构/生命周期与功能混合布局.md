# 生命周期 + 功能混合布局与归属表

## 目标与范围

本文档用于冻结 `Assets/Scripts/Manager/` 的继续膨胀风险，并明确 GoHome 在后续迁移中的目录归属规则。

- 本批次仅定义规则与归属，不进行代码移动。
- 顶层按生命周期：`App` / `Session` / `Level` / `UI`。
- 子层按功能域：`Root` / `Flow` / `Progress` / `Combat` / `Player` 等。

## 推荐目录骨架（规则目标）

> 说明：这是迁移目标结构，不代表当前文件已全部落位。

- `Assets/Scripts/App/`
  - `Root/`：`AppRoot`、`Bootstrapper`
  - `Services/`：`SaveSystem`、`SceneLoader`
  - `Config/`：`ConfigRegistry`
- `Assets/Scripts/Session/`
  - `Root/`：`SessionRoot`
  - `Player/`：`PlayerStateManager`、`PlayerResourceService`
  - `Progress/`：`RouteProgressManager`
  - `Inventory/`：`InventoryManager`
  - `Traits/`：`TraitManager`
- `Assets/Scripts/Level/`
  - `Root/`：`LevelRoot`
  - `Flow/`：`AdvanceFlowController`、`ActionManager`、`RestManager`
  - `Combat/`：`BattleManager`
  - `Events/`：`EventManager`、`EnemyPoolService`
- `Assets/Scripts/UI/`
  - `Menu/`：`MainMenuController`
  - `InGame/`：`InGameSettingsController`、`UIManager`

## 生命周期所有权表（现有核心对象）

| 生命周期层 | 代表根对象 | 典型职责 | 现有核心脚本（示例） |
| --- | --- | --- | --- |
| App | `AppRoot` | 启动、跨局资源、配置与场景切换 | `Bootstrapper` `SaveSystem` `SceneLoader` `ConfigRegistry` |
| Session | `SessionRoot` | 一局/一次游玩会话中的玩家与进度状态 | `PlayerStateManager` `PlayerResourceService` `RouteProgressManager` `InventoryManager` `TraitManager` |
| Level | `LevelRoot` | 关卡内行动流、事件、战斗调度 | `AdvanceFlowController` `ActionManager` `RestManager` `BattleManager` `EventManager` `EnemyPoolService` |
| UI | UI 根节点（由 `UIManager`/Router 体系驱动） | 面板开关、输入交互、视图刷新 | `UIManager` `MainMenuController` `InGameSettingsController` |

## 判定规则（归属优先级）

当脚本职责存在交叉时，按以下顺序判断：

1. 是否直接承载生命周期根容器能力（是则归 `*Root`）。
2. 是否持有会话/关卡运行态并参与流程编排（是则归 `Session` 或 `Level` 下对应功能域）。
3. 是否主要处理 UI 输入与界面交互（是则归 `UI/*`，并使用 `*Controller` 后缀）。
4. 是否为无场景状态基础能力（是则归 `App/Services` 或对应层 `Services`）。

## 迁移门禁（本批次先软后硬）

- 软门禁（立即生效）：
  - 新增脚本默认不得进入 `Assets/Scripts/Manager/`。
  - 允许“迁移触达改动”在旧目录临时补丁，但需在 PR/提交说明标注原因。
- 硬门禁（后续批次启用）：
  - 在目录稳定后，CI/审查规则将拒绝新增 `Assets/Scripts/Manager/*.cs`（白名单除外）。
  - 每批只迁移一个生命周期块，顺序建议：`App -> Session -> Level -> UI`。

## 本文档与重构边界

- 本文档属于架构规则，不要求在本批次修改现有脚本路径。
- 代码迁移与引用修复在后续批次执行，按门禁逐步推进与回滚验证。
