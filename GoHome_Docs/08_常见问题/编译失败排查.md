# 编译失败排查（先判断是否“缺文件/缺类型”）

本页用于处理“打不开项目/编译不过”的情况，优先把问题分成：**缺文件**、**命名空间/程序集引用**、**API 不存在** 三类。

## 概念与边界

- Unity 的 C# 编译失败往往不是“一个错误”，而是**第一处错误**导致后面连锁报错。
- 先解决最上面的 1–3 个 error，再看后续是否消失。

## 常见错误与症状

### 1) 缺文件/缺类型（最常见）

症状：
- `CS2001: Source file ... could not be found`
- `CS0246: The type or namespace name 'Xxx' could not be found`

定位与动作：
- 如果日志里是某个 `.cs` 路径不存在：先确认该文件是否被误删/改名
- 如果是类型找不到：多半是文件没被编译进来、命名空间不对、或 asmdef 隔离

### 2) asmdef/程序集引用问题

症状：
- 某些目录下的脚本互相看不到类型
- Editor 脚本能编译，Runtime 报错（或反过来）

定位与动作：
- 检查对应目录是否有 `.asmdef`，以及引用列表是否缺少需要的程序集

### 3) API/包版本不一致

症状：
- `CS1061: 'Xxx' does not contain a definition for 'Yyy'`
- 明明以前能用的 API 现在报错

定位与动作：
- 检查 `Packages/manifest.json` 与 Unity 版本差异
- 优先用项目内现有写法对齐，而不是引入新包/新 API

## 如何修改（建议顺序）

1. 先抓“第一处错误”的文件与行号
2. 再确认是缺文件还是缺引用
3. 最后才考虑“代码逻辑写错”

## 验证清单

- Console 错误数量明显减少（先解决 top errors）
- 进入 PlayMode 不再出现脚本编译失败提示
- 若仍失败：把最新前 20 行错误日志贴出来再定位（不要贴全部）
