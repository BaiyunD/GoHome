# 运行时空引用排查（NullReferenceException）

本页用于处理 PlayMode 下最常见的空引用：Inspector 未绑定、单例未初始化、资源加载返回空、事件订阅时机不对。

## 概念与边界

- `NullReferenceException` 不是根因，它是“某个必需引用为 null”的结果。
- 排查关键：找到 **第一个出现的 NRE** 的堆栈顶部方法，确认“该引用本应在哪里被赋值/绑定”。

## 常见错误与症状

### 1) Inspector 字段未绑定（UI 最常见）

症状：
- 打开面板后文本不刷新或直接 NRE

定位与动作：
- 查面板脚本的 `[SerializeField]` 字段是否绑定
- 约定：缺绑定应 `Debug.LogError` 明确指出字段名（见 UI 章）

参考：
- [`../05_UI与交互/Inspector绑定与严格校验.md`](../05_UI与交互/Inspector绑定与严格校验.md)

### 2) 单例/Manager 未挂载

症状：
- `XxxManager.Instance` 为 null
- 只在某些场景出现（场景切换后才出现）

定位与动作：
- 检查该 Manager 是否需要在场景中存在一个实例
- 检查 `Awake/Start` 初始化顺序与 DontDestroyOnLoad 策略

### 3) Resources.Load 返回 null

症状：
- 地区/配置加载为空，后续使用时报 NRE

定位与动作：
- 先检查加载路径与资源目录结构是否一致
- 缺资源应有明确日志（输出路径与上下文）

参考：
- [`../06_配置与数据/Resources加载与目录约定.md`](../06_配置与数据/Resources加载与目录约定.md)

### 4) 事件订阅/解绑不对

症状：
- 同一 UI 刷新多次、或对象销毁后仍收到回调导致 NRE

定位与动作：
- 检查 `OnEnable` 订阅是否在 `OnDisable` 解绑
- 避免在 `Start` 订阅但在 `OnDisable` 没解绑导致泄漏

## 如何修改（建议顺序）

1. 先定位：堆栈顶部脚本与方法
2. 再判断：是“绑定缺失”还是“初始化顺序/加载为空”
3. 补齐：严格报错（包含字段名/路径/上下文）

## 验证清单

- 重新进入 PlayMode 后不再出现 NRE
- 缺配置时能看到更早、更明确的错误日志（避免拖到 NRE）
