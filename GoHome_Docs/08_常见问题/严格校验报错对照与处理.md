# 严格校验报错对照与处理（hard fail）

本页用于处理“配置缺失导致流程中断”的错误。原则：**宁可早失败，也不要带着坏数据继续跑到后面 NRE**。

## 概念与边界

- 严格校验：发现关键配置缺失/非法时立即报错并中断流程（例如前进/探索、事件筛选、开战）。
- 这些错误应该携带足够上下文（`regionCode/enemyId` 等），保证一次定位。

## 本项目常见严格校验点

### 1) regionCode 校验失败

典型来源：
- 构建当前地区码后（前进/探索流程）
- 事件筛选前：`GetRandomEventByRegionCode(currentRegionCode)`
- 敌人解析前：按地区池解析敌人

处理动作：
- 回到“地区码来源”的那一层修复（通常是路线进度/子地区设置）

参考：
- [`../06_配置与数据/regionCode与enemyId规范与校验.md`](../06_配置与数据/regionCode与enemyId规范与校验.md)

### 2) enemyId 为空/找不到敌人

典型来源：
- 事件结果为遇敌但未填写 `enemyId`
- 当前地区池中找不到该 `enemyId`

当前实现提示：
- 事件结果 `enemyId` 为空时，事件链路会跳过开战（不进入 `StartBattleByEnemyId`），不一定抛 hard fail。

处理动作：
- 先检查事件资产的遇敌结果是否填了 `enemyId`
- 再检查 `EnemyData` 是否配置了对应 `enemyId/regionCode`
- 最后检查 `EnemyPoolService` 是否把该敌人加入列表

参考：
- [`../06_配置与数据/事件与敌人数据_编辑器配置.md`](../06_配置与数据/事件与敌人数据_编辑器配置.md)
- [`../03_功能模块/战斗与敌人数据.md`](../03_功能模块/战斗与敌人数据.md)

## 常见错误与症状

- 只看到“无法开始战斗”，但不知道是哪个地区/哪个 enemyId
  - 修复方向：让报错信息携带 `regionCode/enemyId`
- 失败发生在太晚的位置（已经扣了资源/开了 UI）
  - 修复方向：把校验前移到分支入口处（当前部分链路仍是“先扣后校验”）

## 如何修改（入口/文件/方法）

- regionCode 校验工具：`Assets/Scripts/GameEvent.cs`
  - `EventCondition.ValidateRegionCodeOrThrow(...)`
- enemyId/地区池解析：`Assets/Scripts/Manager/EnemyPoolService.cs`
- 开战入口：`Assets/Scripts/Manager/BattleManager.cs`（`StartBattleByEnemyId`）

## 验证清单

- 缺配置时能在最早阶段失败（不拖到 NRE）
- Console 日志包含 `regionCode/enemyId` 与调用上下文
- 修复配置后链路闭环：事件遇敌 → 开战成功 → UI 正常刷新
