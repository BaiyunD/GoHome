## 敌人逃跑（配置约定）

- **开关**：[`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 的 **敌人行为** 中勾选 `CanEscape`。
- **概率**：与玩家共用基类 [`CharacterDataBase`](../../Assets/Scripts/Data/CharacterDataBase.cs) 的 **`escapeRate`（Inspector：战斗属性，0~100）**；敌人行动结算前掷骰，成功则 `BattleResult.EnemyEscape` 结束战斗（无当次普攻）。
- **结算叙述**：[`BattleManager`](../../Assets/Scripts/Level/Combat/BattleManager.cs) 在 `EventNarrationModal` 中展示 **`{characterName}逃跑了~`**；名称为空时兜底为 **「敌人逃跑了~」**。
- **已移除**：`EnemyData` 不再包含单独的「敌人逃跑百分点」序列化字段；旧资产里若残留同名 YAML 键可忽略或手动删掉。

## 敌人开战狠话（EventNarrationModal）

- **配置字段**：[`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 的 **开战叙述** 区块 `battleOpeningTaunt`（属性 `BattleOpeningTaunt`），字符串；可为空。
- **显示时机**：[`BattleManager.StartBattle`](../../Assets/Scripts/Level/Combat/BattleManager.cs) 在战斗 UI 打开成功后读取当前 `EnemyRuntime.RuntimeData` 上的狠话；非空则 `UIManager.ShowEventNarrationModal`；为空则 `ClearEventNarrationModalText` + `HideEventNarrationModal`，避免沿用上一场叙述。
- **清除时机**：玩家 **首次** 成功下发战斗指令（普攻或逃跑，`IssuePlayerCommand`）时再次 `ClearEventNarrationModalText` + `HideEventNarrationModal`，与空狠话分支走同一套 dismiss，避免状态残留。

## 敌人分类（小怪 / 精英 / BOSS）

- **配置**：[`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 的 **敌人分类** 区块 `enemyKind`（枚举 `EnemyKind`：`Minion` 小怪、`Elite` 精英、`Boss`）；默认小怪，按资产逐敌配置。
- **战斗面板标题**：[`BattleManager.GetEnemyDisplayName`](../../Assets/Scripts/Level/Combat/BattleManager.cs) 供 [`BattlePanel`](../../Assets/Scripts/UI/InGame/Panels/BattlePanel.cs) 使用——小怪为 `名字 LV等级`；精英为 `名字（精英） LV等级`；BOSS 为 `名字（BOSS） LV等级`。
- **叙述用短名**：`GetEnemyBaseName` 仍为纯 `CharacterName`，不带分类标签与等级，供逃跑叙述、战报上下文等使用。
- **胜利基础三选一倍率**：仅作用于 `BattleManager` 上 `baseVictoryAttackDelta` / `baseVictoryDefenseDelta` / `baseVictoryMaxHpDelta` 传入胜利结算与 [`BattleVictorySettlementContext`](../../Assets/Scripts/Session/Combat/BattleVictorySettlementContext.cs)（含幸运石追加那次基础三选一）的数值；小怪 ×1、精英 ×2、BOSS ×3。**不**倍率 `commonRewards` / `extraRewards` 中的物品与金钱。

## 战斗结算（MVP）

- **双归 0**：双方 `CurrentHp` 同时 ≤0 时判 **玩家失败**（`BattleResult.Lose`），不判胜。实现见 [`BattleManager.EvaluateBattleEndByHp`](../../Assets/Scripts/Level/Combat/BattleManager.cs)。
- **结算中继**：[`BattleManager.EndBattle`](../../Assets/Scripts/Level/Combat/BattleManager.cs) 在清空敌人 `EnemyStateManager.ClearCurrent` **之前** 用 [`BattleSettlementRewardSnapshot.FromEnemyData`](../../Assets/Scripts/Session/Combat/BattleSettlementRewardSnapshot.cs) 拷贝奖励；清空后构造 [`BattleSettlementContext`](../../Assets/Scripts/Session/Combat/BattleSettlementContext.cs)，由 [`BattleSettlementRelay.Dispatch`](../../Assets/Scripts/Session/Combat/BattleSettlementRelay.cs) 按 `BattleResult` 分发到 [`BattleWinSettlement`](../../Assets/Scripts/Session/Combat/BattleWinSettlement.cs) / [`BattleLoseSettlement`](../../Assets/Scripts/Session/Combat/BattleLoseSettlement.cs) / [`BattleFleeSettlement`](../../Assets/Scripts/Session/Combat/BattleFleeSettlement.cs)；叙述再交给 `BattleEnded` 与 `ShowEventNarrationModal`。胜利结算后会再次调用 `UIManager.UpdateInfo()` 刷新 HUD。
- **胜利基础奖励（Inspector）**：`BattleManager` 上 `baseVictoryAttackDelta` / `baseVictoryDefenseDelta` / `baseVictoryMaxHpDelta`（默认 1 / 1 / 5）；胜利时先按当前敌人的 [`EnemyKind`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 乘倍率（小怪 1、精英 2、BOSS 3），再 `Random.Range(0, 3)` 三选一写入 `PlayerRuntime`；最大生命增加后 `CurrentHp = Min(CurrentHp, MaxHp)`，不自动补满。
- **敌人常见 / 额外奖励**：[`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 的 `commonRewards`、`extraRewards`（元素为可序列化 `BattleRewardEntry`：`kind` 为物品或金钱）；`extraVictoryDescription` 为胜利叙述末尾追加的自定义句（可为空）。物品名由 [`BattleWinNarrationComposer.TryResolveItemDisplayName`](../../Assets/Scripts/Session/Combat/BattleWinNarrationComposer.cs) 经 `ItemRegistry` 解析，缺省为 `Item(id)`；金钱文案与分位换算走 `MoneyUtil`。**常见奖励**在胜利叙述中无任何有效条目时，[`BattleWinNarrationComposer.Compose`](../../Assets/Scripts/Session/Combat/BattleWinNarrationComposer.cs) 会在基础属性句之后输出 **「没发现掉落物！」**（仍可有「获得…」中的额外奖励片段，若将来传入）。
- **已移除字段（历史）**：`expReward`、`moneyReward`、`onWinEffects`、`onLoseEffects`、`onEscapeEffects` 与 `BattleResultEffect` 已从 [`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 脚本及主敌人 `Enemy_*.asset` 中删除；奖励与叙述请只配置 `commonRewards` / `extraRewards` / `extraVictoryDescription` 并走结算中继。
