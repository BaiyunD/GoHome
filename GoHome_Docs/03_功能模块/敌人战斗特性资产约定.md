# 敌人战斗特性资产约定

## 当前实现

- **权威配置**：在敌人资产 [`EnemyData`](../../Assets/Scripts/Data/Combat/EnemyData.cs) 的 **战斗特性（资产）** 列表 `battleTraits` 中挂载 `EnemyBattleTraitAsset`（ScriptableObject）。与 `traitIds` / `TraitDatabase` 无强制绑定；战斗内仅读取本列表。
- **创建资产**：菜单 `GoHome/Combat/Enemy Battle Trait`，配置 `traitDisplayName`、触发时机、效果行、可选特殊句/风味句。
- **执行与日志**：[`EnemyBattleTraitRunner`](../../Assets/Scripts/Level/Combat/EnemyTraits/EnemyBattleTraitRunner.cs) 在 [`BattleManager`](../../Assets/Scripts/Level/Combat/BattleManager.cs) 中两处调用：
  - **OnEnemyReceiveHit**：玩家对敌伤害结算完成后，将文案合并进 **当次玩家攻击** 结算里 `BattleAttackEvent` 的 **`DefenderPhaseLogSuffix`**（与 `BattleItemHookRunner.RunPlayerBeforeAttack` 产出的 defender 文案之间用 `。` 拼接；**顺序**：先物品/钩子 defender 段，再敌人受击特性段）。
  - **OnEnemyAttackEnd**：敌攻伤害结算且 `AppendEnemyAttackAfterReceiveToSettlement`（玩家 `AfterReceiveHit` 物品）执行完毕后，将文案合并进 **当次敌攻** 的 **`AfterAttackPhaseLogSuffix`**（仍在敌回合结算展示之前）。
- **多特性**：同一列表内按 **数组顺序** 依次执行；多条特性各自产出 `【…】` 段，段与段之间用 **`。`** 拼接（与现有后缀合并规则一致）。
- **门槛（可选）**：资产上可勾选「仅当本下对敌实际扣血 > 0」「仅当本下对玩家实际扣血 > 0」；默认不勾选时，**0 伤仍触发**（与规划口径一致）。
- **数值**：通过 [`CharacterRuntimeStats`](../../Assets/Scripts/Level/Combat/Model/CharacterRuntimeStats.cs) 的 `AddAttackModifier` / `AddDefenseModifier` / 各率类 `Add*RateModifier` / `AddCriticalDamageModifier` 等生效；战斗快照在战斗结束时丢弃，**不写回**大地图玩家属性（与仅同步 HP 的现状一致）。

## 日志格式

单条特性展示为：

`【{敌人名}使用[{特性名}]，{正文}。】`

其中正文由 **通用效果句**（按 `EnemyTraitEffectKind` 模板生成）、**特殊句**（`specialClause` + `specialClauseSlot`）、**风味句**（`flavorClause`，始终在括号内最后一段）组合而成。单条效果行可填 **自定义文案** 覆盖该行的模板。

纯文案、无数值：效果行 `Kind` 选 `None`，并填写 **自定义文案**。

## 验收建议

1. **受击 0 伤**：不勾选「仅当对敌扣血」时，玩家攻击对敌 0 伤害仍应执行 `OnEnemyReceiveHit` 并合并 defender 后缀（若有可执行/可展示内容）。
2. **敌攻后顺序**：同一条敌攻日志中，应先出现玩家 `AfterReceiveHit` 合并后的 defender 段，再出现 `OnEnemyAttackEnd` 合并的 **AfterAttack** 段。
3. **修饰生效**：配置玩家攻防/暴击率等 delta 后，后续 `NormalAttackResolver` 使用的快照数值应已变化。

## 规划/可选改造

- **持续状态**：中毒每回合掉血、叠层等可在 `BattleManager` 增加状态字典并在回合边界结算（当前首版未接回合开始 DoT）。
- **Editor 校验**：为 `EnemyTraitEffectKind` 与模板表做枚举全覆盖检查（当前运行时缺模板会 `Debug.LogWarning`）。
