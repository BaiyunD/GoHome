# 随机事件与遇敌中转（Event → enemyId）

本页覆盖“按地区筛选随机事件、执行事件结果，以及遇敌时只传 `enemyId` 进入战斗”的改动入口与验证要点。

> 架构背景：[`../02_核心架构/整体设计.md`](../02_核心架构/整体设计.md)  
> 模块导航：[`../02_核心架构/模块划分.md`](../02_核心架构/模块划分.md)

## 你要改什么（常见目标）

- 新增/修改事件数据结构（条件、结果、选项）
- 按地区（`regionCode`）筛选事件池
- 新增一种事件结果类型（例如给资源、扣属性、触发遇敌）
- 修正“遇敌”的联动：事件侧只产出 `enemyId`，战斗侧按地区池解析

## 从哪里进（入口链路）

1. `AdvanceFlowController` 走到“随机事件分支”
2. `EventManager` 选择事件并打开事件 UI
3. 玩家点击选项 → `EventManager` 执行 `ApplyEventResult`
4. 若结果为遇敌：返回 `enemyId`（字符串）给流程控制器
5. 流程控制器调用 `BattleManager.StartBattleByEnemyId(regionCode, enemyId)`

## 改哪里（最小改动路径）

### 1) 事件数据结构（条件/结果）

- 文件：`Assets/Scripts/GameEvent.cs`
- 核心约定：
  - `EventCondition.regionCode` 使用 `main_sub` 格式
  - 遇敌结果包含 `enemyId`（字符串）
  - `ValidateRegionCodeOrThrow(regionCode, context)` 用于严格校验

### 2) 事件筛选（按 regionCode）

- 文件：`Assets/Scripts/Manager/EventManager.cs`
- 入口：`GetRandomEventByRegionCode(currentRegionCode)`
- 要求：
  - `currentRegionCode` 必须先通过严格校验；否则应立即失败（不要返回“随便一个事件”）
  - 筛选时只读数据，不要在筛选阶段修改状态（避免随机性与可复现性问题）

### 3) 执行结果（ApplyEventResult）

- 文件：`Assets/Scripts/Manager/EventManager.cs`
- 建议流程：
  - 所有数值/物品变更都集中在 `ApplyEventResult`
  - 遇敌分支：只返回 `enemyId`（不要创建/传递 `EnemyData` 对象引用）

## 遇敌中转规范（必须保持）

- **事件系统输出**：`enemyId`（string）
- **战斗系统输入**：`StartBattleByEnemyId(regionCode, enemyId)`
- **敌人解析位置**：`EnemyPoolService`（按地区池 + ID 查找）

这样做的好处：
- 事件不需要引用/依赖敌人资产（降耦合）
- 地区池可以复用同一个 `enemyId` 的不同版本（按地区变体）

## 怎么验（必须验证项）

- **地区筛选正确**：同一份事件池在不同地区命中集合不同
- **严格校验生效**：
  - `regionCode` 为空或格式错误 → 事件不会被触发（应中断并报错）
  - 遇敌结果 `enemyId` 为空 → 当前实现为“不会进入战斗”（不做 hard fail）
- **遇敌值传递**：事件侧不持有 `EnemyData` 引用，战斗侧才解析
