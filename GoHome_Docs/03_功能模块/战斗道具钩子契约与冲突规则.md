# 战斗道具钩子契约与冲突规则

本页定义战斗类道具（D 组）的统一接入协议，目标是让 item206/item207/item209/item211/item212/item213 后续接入时不互相冲突、不返工。

## 1) Battle Hook 契约（时机与上下文）

### 钩子时机（按推荐最小集合）

- `BattleStart`：战斗开始后、首回合前（初始化层数/临时状态）
- `BeforeAttack`：攻击方出手前（改写攻击系数、附加标签）
- `BeforeReceiveHit`：防守方受击前（减伤、护盾、格挡计算）
- `AfterAttack`：攻击生效后（吸血、割裂后效、追加奖励判定）
- `AfterReceiveHit`：受击结算后（反弹、受击触发增益）
- `TryFlee`：逃跑判定前（改写逃跑率）
- `BattleEnd`：战斗结束（清理临时状态、结算遗留效果）

### 上下文字段（`BattleEffectContext`）

- `Hook`：当前触发时机
- `Owner`：效果所属侧（玩家/敌人）
- `Attacker` / `Defender`：本次交互双方运行时属性
- `ComputedDamage`：基础计算后的伤害
- `FinalDamage`：最终伤害（允许链路修正）
- `FleeRate`：逃跑判定使用值（`TryFlee` 触发时）
- `TurnIndex`：回合序号（用于限次/分段触发）

## 2) 固定优先级与冲突处理

战斗同一时机多个效果并存时，固定按以下顺序执行：

1. **覆盖型硬规则**：免疫/无敌/必定命中（先定可否继续）
2. **乘区修正**：伤害倍率、全战斗属性系数
3. **加减区修正**：攻击/防御/护盾/固定减伤
4. **最终钳制**：`FinalDamage = max(0, value)` 与上限限制
5. **结算后触发**：吸血、反弹、日志与表现

冲突裁定规则：

- 同层同类型：按 `effectId` 字典序稳定排序（确保可复现）
- 乘区先于加减区，避免“先加后乘”与“先乘后加”在不同道具组合下漂移
- 反弹使用“本次实际受伤值”作为上限来源，禁止基于理论伤害反弹
- 吸血基于“攻击方最终造成伤害”，禁止对 0 伤害吸血

## 3) 战斗类 item 钩子映射（规划）

- item206 嗜血匕首
  - `AfterAttack`：按触发概率判定，命中后治疗 `最终造成伤害 * 21%`
- item207 皮衣
  - `BeforeReceiveHit`：按概率触发减免（上限可配置）
  - `AfterReceiveHit`：按“实际受伤”执行反弹
- item209 幸运石
  - `BattleEnd`（胜利时）：概率触发额外物资结算（复用物资服务）
- item211 黑刀
  - `BeforeAttack`：触发时提高伤害 `10% * LV`
- item212 红夹克
  - `BeforeReceiveHit` / `AfterReceiveHit`：受击概率触发防御层数与回血
- item213 晓风披肩
  - `BattleStart`：注入全战斗属性增益
  - `BeforeAttack`：附加“帅呆/拉风”对应敌方修正

## 4) 测试矩阵（编码前）

- 单效测试：每个 item 单独验证触发概率、数值、日志文本
- 组合测试：206+211、207+212、212+213、206+207 等高冲突组合
- 边界测试：0 伤害、极高防御、满血吸血、最低/最高等级
- 回归测试：逃跑率显示与判定一致、战斗结束状态清理、非战斗功能不回归

建议最小自动化断言：

- 伤害永不为负数
- 反弹值不超过本次实际受伤
- 吸血不超过本次伤害 * 系数
- 同输入种子下多次运行结果一致（排序稳定）

## 5) 实现前置清单

- 已有战斗入口统一通过 `ItemEffectDispatcher.ApplyBattleHook`
- `TryFlee` 钩子在逃跑判定前接入（与 UI 显示同源）
- 为战斗效果增加独立日志标签（便于排错）
- 先落地 item206/item207 作为第一批样例，再扩 item211/item212/item213/item209
- 每新增一个战斗效果资产，同步补一条回归用例到 `07_排错与调试` 清单
