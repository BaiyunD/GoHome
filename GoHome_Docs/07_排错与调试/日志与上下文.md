# 日志与上下文：怎么写“可定位的错误”

本页目标：让错误日志一次就能定位，不需要反复猜“是哪个地区/哪个 ID/哪条链路”。

## 概念与边界

- **Debug.Log**：用于开发观察（可以冗余）
- **Debug.LogWarning**：可继续运行但需关注（降级路径）
- **Debug.LogError**：配置/绑定/关键假设被破坏（需要立刻修）
- **throw/中断**：用于严格失败（hard fail），避免带着坏数据继续跑

## 本项目约定（推荐）

### 1) 错误信息必须带上下文

至少包含以下要素中的 2–3 个：
- `context`：调用场景（例如 `AdvanceFlowController.TryExplore`）
- `regionCode`：当前地区码
- `enemyId`：遇敌 ID
- `panel/field`：UI 面板名与字段名（Inspector 绑定缺失时）

### 2) 日志要指向“下一步动作”

不要只写“失败了”，要写“该去哪里改/绑”：
- “请在 Inspector 绑定 `enemyHpText`”
- “请检查 `EnemyPoolService` 是否包含该 `enemyId`（regionCode=...）”

## 常见错误与症状

- **错误信息缺上下文**：只能看到“找不到敌人”，无法判断是配置缺失还是地区池为空
- **打印太晚**：已经扣了资源/开了 UI 才发现数据不合法，导致状态不一致

## 如何修改（入口/文件/方法）

优先在“边界处”补日志/校验：
- 构建 `regionCode` 后（前进/探索流程入口）
- 事件筛选前（`GetRandomEventByRegionCode`）
- 开战解析前（`StartBattleByEnemyId` + `EnemyPoolService`）
- UI 刷新时（关键字段 `null` 的 Inspector 绑定校验）

## 验证清单

- 报错日志里能直接看到 `context + regionCode/enemyId`
- 缺绑定/缺配置时不会拖到 NRE（更早失败）
- 修复一次配置后能闭环跑通（不出现“修了 A 又冒出 B”）
