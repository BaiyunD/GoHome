# 严格校验的定位与前移（hard fail）

本页回答两件事：

- 遇到 hard fail 时，如何快速定位是“缺配置”还是“链路传参错”
- 如何把校验前移到更早的位置，避免拖到后面 NRE 或 UI 状态不一致

## 概念与边界

- “严格校验”不是为了让游戏更容易报错，而是为了让错误**更早、更可定位**。
- 校验要放在“边界处”：输入刚进入系统时（例如 regionCode 构建后、开战解析前）。

## 本项目常见 hard fail 点

### 1) regionCode 非法

典型触发：
- `AdvanceFlowController` 构建当前地区码后
- `EventManager` 按地区筛选事件前

定位要点：
- 看报错里的 `context` 与 `regionCode`
- 再回到“地区码来源”：路线主/子地区是否正确

### 2) enemyId 为空 / 地区池找不到 enemyId

典型触发：
- 事件遇敌结果 `enemyId` 未填
- `EnemyPoolService` 地区池不包含该敌人

定位要点：
- 看报错里的 `regionCode + enemyId`
- 先修编辑器配置（事件/敌人/池），再看是否需要改代码

## 当前实现（先对齐现状）

- 前进流程中，资源扣除发生在 `ExecutePrepareStage`，地区码相关校验在后续阶段执行。
- 事件执行里，遇敌结果 `enemyId` 为空时，当前行为是“不触发战斗”，不是 hard fail。

## 如何修改（把校验前移，作为改造项）

原则：越靠近输入边界越好。

- 输入来自路线/流程：
  - 建议在构建 `regionCode` 后立刻校验；失败就中断（可进一步前移到扣除前）
- 输入来自事件结果：
  - 建议在遇敌结果产生 `enemyId` 的那一刻校验；为空立即失败
- 输入来自外部 UI：
  - 在 UI 刷新入口处校验引用是否绑定（避免拖到 NRE）

## 验证清单

- 缺配置会在最早阶段失败（不会拖到后面 NRE）
- 报错包含足够上下文（`context + regionCode/enemyId`）
- 修复配置后链路闭环（前进/事件/遇敌/战斗/UI 刷新都能跑通）
