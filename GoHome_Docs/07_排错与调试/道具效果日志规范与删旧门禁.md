# 道具效果日志规范与删旧门禁

本页用于统一道具效果日志字段，并提供“删除旧逻辑”前的门禁检查单。

## 1. 日志字段规范

建议统一字段：

- `itemId`
- `effectId`
- `hook`
- `source`（`Asset`/`Builtin`/`Legacy`）
- `triggered`（`true`/`false`）
- `result`（可选：掉落摘要/恢复量/伤害修正）

示例：

- `ItemEffect -> itemId=214 effectId=advance_extra hook=AdvanceSupply source=Asset triggered=true result=发现【木柴】*1`

## 2. 来源日志策略

- 命中 `Builtin` 时打一次 warning（按 item 去重）。
- 进入 `Legacy` 回退时打 info，明确回退原因（无资产/无内建映射/执行失败）。
- 禁止无来源标记的效果日志。

## 3. 删旧门禁（必须全部通过）

- G1：连续 3 轮回归无“重复触发”与“漏触发”。
- G2：重点 item 的 `source=Asset` 命中率达到预期（不再长期依赖回退）。
- G3：关键链路都有日志：`Passive/AdvanceSupply/Use/Rest/Battle`。
- G4：删除清单冻结并完成评审（明确每条旧逻辑影响范围）。

## 4. 删除顺序

1. 删除重复高风险分支（会双触发的逻辑）。
2. 删除低频兼容回退（已全资产化部分）。
3. 删除 `effectKey` 字段及相关引用。

## 5. 回滚预案

- 每次删除旧逻辑前保留可回滚 commit。
- 若线上或联调发现关键行为缺失，优先临时恢复回退链路。
