# 开发流程

## 目标

建立“规划 -> 实现 -> 自检 -> 同步文档”的最短闭环，避免跑偏与知识断层。

## 推荐流程（准确优先）

1. **命中知识库**
   - 先从 `GoHome_Docs/README.md` 目录找到相关主题
   - 再进入对应章节/文档，阅读“常见修改路径/风险与校验”
2. **规划确认**
   - 需求不清楚或有多解时，先问清楚再动手
3. **实现**
   - 只做本次需求涉及的最小改动，避免顺手重构导致风险扩大
4. **自检**
   - 至少做一次静态自检（例如 lint/编译）与关键流程回归
5. **同步记录**
   - 当日实现过程记录写入 `DEVLOG.md`
   - 只有当“长期指南内容发生变化”时，才更新 `GoHome_Docs/` 下对应文档

## 输出约定（给 AI 与人都可用）

- 修改文件清单
- 每个文件关键改动
- 验证结果（至少包含 lint）
- 需要在 Unity Inspector 手动补的字段/绑定项
