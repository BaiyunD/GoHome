# 代码格式与最小改动原则

## 目标

在 Unity 项目中，优先保证“改动可控、易回归”。默认策略是最小改动，不做无关重构。

## 代码格式

- **大括号风格**：Allman（大括号换行）
- **缩进**：4 空格（不用 Tab）
- **行宽**：每行尽量不超过 100 字符（必要时换行）

## using 处理

- `using` 放在文件顶部并按字母序排列
- 但：**不要为了“整理”而新增/移除 using**，除非修改内容必须

## 禁止项（项目硬约束）

- 不要重新排列类成员顺序
- 不要修改命名空间
- 不要修改任何 `.meta` 文件

## 最小改动原则

- 只改需求涉及的代码块，不动无关类/方法/变量/注释/空行
- 不“顺手优化/重构”
- 不新增功能，除非明确要求
- 不删除现有代码（含注释/空行），除非明确要求

## 风险与校验

- **高风险**：顺手重构导致改动面扩大，回归难度上升。
- **必查**：变更是否引入 Inspector 需要补绑的字段（否则运行期才暴雷）。
