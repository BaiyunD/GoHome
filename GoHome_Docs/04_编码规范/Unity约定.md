# Unity 约定

## 目标

用一致的 Unity 编码习惯降低隐藏依赖与运行时风险。

## 组件获取

- **优先**：`GetComponent<T>()`
- **避免**：`FindObjectOfType<T>()`

原因（项目约定）：
- `FindObjectOfType` 容易引入全局隐式依赖，且性能与可控性更差；
- 更难定位“到底依赖哪个对象”，容易在场景变更后静默失效。

## 协程

- 协程方法名以 `Coroutine` 结尾，例如：`WaitForAttackCoroutine`
- 协程宿主尽量使用**常驻管理器**或明确生命周期对象，避免 UI 面板隐藏/销毁导致协程中断

## 常见写法建议

- UI 面板显示/隐藏尽量通过 `UIManager` 统一管理，避免多个脚本抢同一面板状态
- 需要在 Inspector 绑定的字段：缺失应输出**明确错误日志**，优先暴露配置问题

## 风险与校验

- **高风险**：在 UI 脚本里直接写业务规则（会导致状态分裂、难以回归）。
- **必查**：场景里是否存在重复单例挂载（会导致 Instance 被覆盖或行为异常）。
