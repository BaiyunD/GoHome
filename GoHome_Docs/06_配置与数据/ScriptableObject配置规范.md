# ScriptableObject 配置规范

本页定义 ScriptableObject（SO）在本项目中作为“可配置数据”的推荐用法，目标是：**可检索、可扩展、缺配置时可定位**。

## 概念与边界

- SO 用于：规则/表/模板数据（地区、敌人、事件、物品等）
- 运行时状态（例如当前 HP、当天数值）不应写回 SO，而应写到运行时快照/PlayerInfo/Manager 状态里

## 本项目约定

- **字段可见性**：统一 `[SerializeField] private` + 只读 `public` 属性
- **ID 字段必须稳定**：例如 `enemyId`，禁止在运行时自动生成或频繁改名
- **跨系统关联用 ID，不用对象引用**（除非明确是“同一资产强绑定”）
  - 例：事件遇敌用 `enemyId` 字符串，而不是 `EnemyData` 引用

## 常见错误与症状

- **用引用耦合**：事件资产引用敌人资产，导致地区变体/池化难做
- **缺字段不报错**：Inspector 漏填，运行时报错但不含上下文，难定位
- **运行时修改 SO**：导致多局共享污染（Editor/PlayMode 下更隐蔽）

## 如何修改（入口/文件/方法）

- 新增一个 SO 字段（例如 `regionCode`）：
  1. 先在数据类（如 `EnemyData`）增加字段与只读属性
  2. 在 Editor Inspector（如自定义 Inspector）同步显示/编辑
  3. 在消费侧（Manager）加入严格校验与清晰错误日志

## 验证清单

- Inspector 能看到并配置该字段
- 缺字段时能在运行时明确报错（包含“资产名 + 字段名 + 上下文”）
- 运行时逻辑只读 SO，不写回
