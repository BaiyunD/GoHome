# 道具效果资产化迁移规范

本页定义“从 itemId 分支迁移到效果资产（ScriptableObject）分发”的统一约定。

## 迁移目标

- 优先使用 `ItemDefinition.effectDefinition`。
- 无效果资产时，允许回退兼容逻辑（`effectKey` 或内置映射）。
- 新增道具优先“配资产”，避免新增 `itemId` 分支。

## 关键代码落点

- `Assets/Scripts/Data/Items/ItemDefinition.cs`
- `Assets/Scripts/Data/Items/Effects/ItemEffectDefinition.cs`
- `Assets/Scripts/Session/Items/Effects/ItemEffectFactory.cs`
- `Assets/Scripts/Session/Items/Effects/ItemEffectDispatcher.cs`

## 工厂与分发器边界

- `ItemEffectFactory`：负责“创建效果实例”（优先 `effectDefinition`，其次内置兼容映射）。
- `ItemEffectDispatcher`：负责“在具体流程时机调用效果实例”。
- 约束：新效果扩展优先改工厂映射或资产配置，不在流程代码散落新增 `itemId` 分支。

## 触发入口

- 被动：`PassiveSystem.Rebuild()` -> `ItemEffectDispatcher.TryApplyPassive`
- 前进/探索物资：`AdvanceFlowController.RunSupplyBranchCoroutine` -> `TryApplyAdvanceSupply`
- 休息：`RestSettlement.ApplyFixedDisplayRules` -> `TryApplyRest`
- 使用消耗品：`ConsumableEffectDispatcher.TryApply` -> `TryApplyUse`

## 兼容优先级

1. 若 `ItemDefinition.effectDefinition` 已配置，则走资产逻辑。
2. 若未配置，走 `ItemEffectFactory` 的内置兼容映射。
3. 若仍无匹配，再回退到旧逻辑（如 `effectKey`）。

- 不在主流程中新增散落 `itemId` 判断。
- 新效果优先扩展 `ItemEffectDefinition` 子类和分发器入口。
- 迁移时保持“行为不变优先”，并输出触发日志便于排错。
