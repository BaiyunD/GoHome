# 事件与敌人数据（代码约束与扩展）

本页面向“要改代码规则/扩展数据结构”的场景：哪些字段必须严格校验、报错应如何包含上下文、以及扩展路径从哪里入手。

## 概念与边界

- “严格校验”指：配置缺失或格式错误时 **立即失败并中断流程**，而不是继续跑到后面 NRE。
- 数据关联优先“ID 值传递”，解析集中在一个地方（例如敌人解析集中在 `EnemyPoolService`）。

## 本项目约定（必须保持）

### 1) regionCode 严格校验

- 校验工具：`EventCondition.ValidateRegionCodeOrThrow(regionCode, context)`
- 校验时机：
  - 构建当前地区码后（前进/探索流程）
  - 筛选事件池前（`GetRandomEventByRegionCode`）
  - 开战解析前（`StartBattleByEnemyId`）

### 2) enemyId 严格校验

- 校验时机：遇敌结果被执行并准备开战时
- 规则：空/空白直接失败；找不到对应 `EnemyData` 也必须失败

### 3) 解析集中化

- 事件系统只产出 `enemyId`，不要依赖敌人资产
- 战斗系统调用 `EnemyPoolService` 获取 `EnemyData`
- 地区池/ID 查找逻辑只在 `EnemyPoolService` 写一份

## 常见错误与症状

- 报错没有上下文：只看到“找不到敌人”，不知道是哪个地区/哪个 enemyId
- 校验太晚：前面已经开了 UI/扣了资源，最后才失败导致玩家状态不一致
- 在多个地方复制筛选规则：一个地方改了，另一个地方忘了改，出现“偶现 bug”

## 如何修改（入口/文件/方法）

### 扩展事件结果类型

- 文件：`Assets/Scripts/GameEvent.cs`
  - 扩展 `EventResultType`
  - 扩展 `EventResult` 字段（必要时新增参数）
- 文件：`Assets/Scripts/Manager/EventManager.cs`
  - 在 `ApplyEventResult` 增加对应分支
  - 若涉及战斗/流程中转：返回值或回调只传 ID（不要传对象引用）

### 扩展敌人解析规则

- 文件：`Assets/Scripts/Manager/EnemyPoolService.cs`
  - 扩展“地区池选择”或“按权重随机”的策略
  - 保持错误信息包含 `regionCode/enemyId`

### 扩展战斗入口

- 文件：`Assets/Scripts/Manager/BattleManager.cs`
  - 扩展 `StartBattleByEnemyId` 的前置校验或战斗初始化
  - 确保 UI 打开与 `UpdateInfo()` 刷新顺序稳定

## 验证清单

- 任意缺配置场景都能在**最早时机**失败（不会拖到 NRE）
- 报错信息至少包含：`context` + `regionCode` + `enemyId`
- 扩展后仍保持“事件只传 ID、解析集中在池服务”的边界不被破坏
