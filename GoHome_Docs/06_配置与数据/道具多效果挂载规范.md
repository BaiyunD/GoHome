# 道具多效果挂载规范

本页定义“一个物品挂载多个效果资产”的数据结构与使用约束，作为现有 `effectDefinition` 单挂载方案的演进目标。

## 1. 设计目标

- 支持“通用效果模板 + 特殊效果资产”混合配置。
- 支持单物品同时挂载多个效果（被动/前进/战斗/休息/使用）。
- 保留迁移期兼容：`Asset -> Builtin -> Legacy`。

## 2. 数据结构建议

- 现状：`ItemDefinition.effectDefinition`（单个）
- 目标：`ItemDefinition.effectDefinitions`（列表）

建议字段（规划）：

- `effectDefinitions: List<ItemEffectDefinition>`
- `allowDuplicateEffectType: bool`（默认 false）
- `effectSetVersion: int`（便于回归与存档兼容核对）

## 3. 配置规则

- 通用模板优先复用（如 `StatPassiveEffect`、`ConsumableUseEffect`）。
- 同一物品内，效果资产不允许空引用。
- 默认不允许“同类模板重复挂载”；若确有需求需显式开启并在备注说明原因。
- 资产命名统一：
  - `Effect_<ItemId>_<道具名>_<模板名>`
  - 例：`Effect_210_晓月手链_AdvanceExtraLoot`

## 4. 执行入口约束

- 流程层不直接写 `itemId` 分支判断。
- 流程层只构造上下文并调用 `ItemEffectDispatcher`。
- 每个效果资产只负责“规则计算与结果产出”，不直接弹 UI。

## 5. 迁移策略

1. 先新增列表字段并兼容旧单字段读取。
2. 分批把已迁移 item 从单挂载转为多挂载。
3. 回归稳定后再移除旧单字段。

## 6. 验收要点

- 单物品多效果能按顺序稳定触发。
- 读档后挂载列表与运行时表现一致。
- 未迁移 item 仍可通过回退链路工作。
